## 8GB 内存到底够不够用？

答案：对个人开发者和中小项目的自托管需求，8GB 基本都够。具体一点，下面这些场景在 8GB 上都放得下：

- 一个跑得不轻的 WordPress 站。加上缓存之后，这类站点很少超过 2–3GB 内存。如果它需要更多，问题多半出在某个失控的插件上。
- 一套“应用 + 数据库”的经典组合。Rails、Django、Laravel 或 Node 配 Postgres 或 MySQL，再留点余量给 Redis，这正是 8GB 档最典型的工作负载。
- 8–12 个干普通活的 Docker 容器。
- 一个量化后的 7B 开源模型。4-bit 量化大约占 4–5GB，加上系统占用刚好放得下——CPU 推理速度不快，但能跑。
- 带 headless Chromium 的 AI Agent。浏览器自动化要吃 1–2GB，8GB 是这类需求第一次能舒展开的档位。
- n8n、Coolify、Supabase 这类自托管工具栈，单独部署一个都有富余。

放不下的也说得直白：大于 7B 的模型、上面几种场景同时开、索引很大的 Elasticsearch，以及任何单个进程动辄吃掉几个 GB 的服务。有这类需求，直接看 16GB 的机器。

## 第一个坑：8GB 的机器上，磁盘比内存更值得计较

Linux 会把应用用不完的内存拿来做磁盘缓存。32GB 的机器跑 8GB 的负载，剩下 20 多 GB 都能当缓存，磁盘几乎摸不到；8GB 的机器跑 6GB 的负载，缓存只剩不到 2GB，数据库和应用会频繁直接读写磁盘。所以在 8GB 这个档位，磁盘就在关键路径上，读写慢一拍，整个应用跟着慢。

由此得出的选购规则很简单：如果要在 8GB 机器上跑数据库，优先选 NVMe，容量反而可以往后放——磁盘容量以后随时能扩，延迟补不回来。

## 几个常见问题

**8GB VPS 能同时跑网站和数据库吗？**

可以，这恰好是 8GB 最经典的用法。一个中等流量的 Web 应用加 Postgres 或 MySQL，再留位置给 Redis，8GB 通常还有余量。

**8GB 能跑本地大模型吗？**

4-bit 量化的 7B 模型约占 4–5GB，放得下，用 CPU 推理速度会比较慢；超过 7B 的模型在这个档位跑不动。

**4TB 月流量够用吗？**

纯自托管和中小站点很难用完。另外别被“不限流量”迷惑——不限量套餐一般附带公平使用条款，实际额度未必比明确写 20TB 或 32TB 的更慷慨。IONOS 是这个档位少数真正不限量的，它也因此有自己的位置。
